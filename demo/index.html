Known limitations of this engine & demo (read before trusting output)
  1. Kashmiri-only Sharada vowels have no real Unicode codepoints yet. This engine writes the nearest Sharada vowel plus a borrowed Devanagari combining diacritic, the Sharada revival community's own workaround — not something with an official codepoint or confirmed font support.
  2. Kashmiri's dental affricates (ژ/ژھ) don't exist in Sharada at all. They're rendered here as nukta-marked ca/cha, a project convention pending community review, not a documented standard.
  3. Long-e/long-i and long-o/long-u share one Perso-Arabic spelling (both write as zer+yeh, or pesh+waw). Converting Perso-Arabic → Sharada will pick one reading; this is a property of the orthography, not a bug.
  4. This demo needs fully-diacritized input. Under-diacritized Perso-Arabic (how Kashmiri is normally typed) needs a diacritizer model first — not wired into this browser demo (see the project README for the CLI's --diacritize flag, which does support it).
  5. None of these mapping choices have been checked by a native Kashmiri speaker against the Sharada revival primers yet. Treat every output on this page as a best-effort guess, not fact.
This page runs a JavaScript port of the actual koshur_sharada Python engine's parsing logic; its codepoint tables are generated directly from the Python source, not retyped by hand. See the project's README.md and CONTEXT.md for the full status and history.
